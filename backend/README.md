# روتینو — بک‌اند

سرور روتینو: احراز هویت با شماره تلفن، سینک چنددستگاهی، اشتراک و پرداخت.

> **این پوشه هنوز دیپلوی نشده.** کد و `docker-compose.yml` آماده‌اند تا هر وقت
> خواستی روی یک Cloud Server آروان بالا بیاید. توسعه و تست به Docker نیاز ندارند.

## اجرا

```bash
npm install
npm test          # تست‌ها روی PGlite اجرا می‌شوند — بدون Docker، بدون پستگرس نصب‌شده
npm run typecheck
```

برای بالاآوردن سرور واقعی روی این دستگاه یک پستگرس لازم است:
```bash
cp .env.example .env
npm run db:push   # اسکیما را روی DATABASE_URL می‌سازد
npm run dev
```

## چرا PGlite

روی این دستگاه Docker نصب نیست. [PGlite](https://pglite.dev) **خودِ پستگرس است
که به WASM کامپایل شده** — نه یک شبیه‌ساز — پس تست‌ها همان SQLی را اجرا می‌کنند که
پروداکشن اجرا می‌کند: همان محدودیت‌ها، همان jsonb، همان تراکنش‌ها.

کل ترفند در `src/app.ts` است: `buildApp(deps)` دیتابیس را **به‌عنوان ورودی**
می‌گیرد و `src/index.ts` تنها جایی است که یک `pg.Pool` واقعی ساخته می‌شود. تست‌ها
PGlite را تزریق می‌کنند و اپ واقعی را با `app.inject()` درایو می‌کنند: بدون پورت،
بدون شبکه، چند میلی‌ثانیه.

**آنچه PGlite نمی‌تواند ثابت کند:** تک‌کانکشن است، پس رقابت روی
`UPDATE users SET seq = seq + $n` یا `SELECT … FOR UPDATE` تست نمی‌شود — یعنی
دقیقاً همان چیزی که این تصمیم‌ها برایش وجود دارند. PGlite **منطق** را ثابت می‌کند،
نه **همزمانی**. برای همین مسیرهای بحرانی همزمانی عمداً **یک statement** هستند که
صحتشان تضمین پستگرس است نه کد ما. تست‌های همزمانی وقتی VM بالا آمد، با
docker-compose.

## معماری

```
src/
  index.ts     تنها جایی که pg.Pool واقعی ساخته می‌شود
  app.ts       buildApp(deps) → FastifyInstance. تست‌ها این را import می‌کنند.
  env.ts       env با zod؛ روی بوت fail-fast
  db/          schema.ts (drizzle) + client.ts (تایپ اتحادیه‌ی node-postgres | pglite)
  routes/      health, plans, …
  services/    pricing (قیمت سمت سرور), …
  providers/   sms/{console,kavenegar}   psp/{fake,zibal}
  lib/         phone.ts  ← باید با src/lib/phone.ts کلاینت یکی بماند
test/
  helpers/pglite.ts     هارنس: PGlite + اسکیما + پلن‌های seed
  phone.parity.test.ts  ← هر دو پیاده‌سازی را import می‌کند و مقایسه می‌کند
```

### دو چیزی که نباید بشکنند

**۱. `phone.ts` باید با کلاینت یکی بماند.** `users.phone` یکتاست و از این تابع
می‌آید. اگر کلاینت و سرور اختلاف پیدا کنند، یک آدم از دو دستگاه لاگین می‌کند، به دو
رشته‌ی متفاوت نرمال می‌شود، **دو ردیف `users`** می‌گیرد و دیتایش نصف می‌شود — بدون
هیچ خطایی. `test/phone.parity.test.ts` تنها چیزی است که جلوی این را می‌گیرد.

**۲. `records.kind` عمداً `feedback` را ندارد.** فیدبک push-only است و جدول
رابطه‌ای خودش را دارد؛ اگر وارد `records` شود به دستگاه برمی‌گردد و تا ابد
re-dirty می‌شود. یک CHECK این را در سطح دیتابیس تضمین می‌کند.

## نکته‌های عملیاتی

- **`seq`**: شمارنده‌ی یکنواخت هر کاربر که با
  `UPDATE users SET seq = seq + $n … RETURNING seq` بالا می‌رود. این کار **قفل
  ردیفی** می‌گیرد و نوشتن‌های آن کاربر را سریالایز می‌کند، پس ترتیب `seq` با ترتیب
  commit یکی است. یک `SEQUENCE` ساده این تضمین را **ندارد**: تراکنش کندتر می‌تواند
  seq کمتری بگیرد و *بعد از* اینکه یک خواننده از آن رد شده commit کند — و آن ردیف
  برای همیشه از آن دستگاه پنهان بماند.
- **clamp**: `updated_at = least(client, serverNow + 60s)` روی هر push. بدون آن،
  یک دستگاه با ساعت ۲۰۹۹ برای همیشه هر تداخلی را در آن اکانت می‌برد.
- **CORS**: اوریجین WebView اندروید `https://localhost` است (چون
  `capacitor.config.ts` مقدار `androidScheme: 'https'` دارد) و iOS
  `capacitor://localhost`. هر دو باید در `CORS_ORIGINS` باشند وگرنه اپ اندروید
  اصلاً نمی‌تواند API را صدا بزند.

## پرداخت

`PSP_PROVIDER=fake` یک درگاه محلی با دکمه‌ی پرداخت/انصراف می‌دهد که **قرارداد زیبال
را عیناً تقلید می‌کند** — همان کدهای نتیجه، همان `201 already verified`. کل ماشین
حالت بدون وابستگی بیرونی تست می‌شود؛ بعد فقط env عوض می‌شود.

سندباکس زیبال با مرچنت `zibal` کار می‌کند (هاست جدا ندارد). **مبلغ‌ها ریال‌اند** و
قیمت‌های اپ تومان — تبدیل ×۱۰ فقط در `services/pricing.ts` انجام می‌شود.

**`callbackUrl` و `localhost`**: زیبال **مرورگر کاربر** را ریدایرکت می‌کند، پس آدرس
باید از دستگاه او در دسترس باشد. برای وب لوکال شاید کار کند، ولی **برای گوشی هرگز**
(`localhost` روی گوشی خودِ گوشی است). برای تست واقعی:
```bash
cloudflared tunnel --url http://localhost:3000
# PUBLIC_API_URL را روی آدرس https تونل بگذار
```

## دیپلوی (وقتی آماده شدی)

```bash
# روی VM آروان
cp .env.example .env    # مقادیر واقعی؛ JWT_SECRET و OTP_PEPPER حتماً عوض شوند
docker compose up -d
```
`docker-compose.yml` شامل postgres + api + caddy + یک job بکاپ شبانه است. Caddy
سرت را خودکار می‌گیرد و **ZeroSSL به‌عنوان issuer جایگزین** کانفیگ شده، چون
اندپوینت‌های ACME لتس‌انکریپت از IP ایران همیشه قابل‌اتکا نیستند.

**بکاپ تست‌نشده تزئین است** — قبل از اتکا، یک restore واقعی روی کانتینر تازه بگیر.
