# 🖥️ راهنمای کامل بک‌اند روتینو

> **بک‌اند یعنی چی؟** سروری که جدا از اپ اجرا می‌شه و کارهایی رو انجام می‌ده که نباید دست کاربر باشه: ورود با پیامک، حساب‌وکتاب اشتراک، پرداخت با درگاه، و پنل مدیریت.
> همه‌ی بک‌اند داخل پوشه‌ی **`backend/`** است و کاملاً مستقل از فرانت اجرا می‌شه (پورت ۳۰۰۰).
>
> اصل طلایی کل بک‌اند: **به کلاینت اعتماد نکن.** قیمت، تخفیف، مدت اشتراک، دوره آزمایشی — همه فقط سمت سرور محاسبه و تایید می‌شن.

---

## ۱. نقشه پوشه‌ی `backend/`

```
backend/
├── src/
│   ├── index.ts          ← نقطه استارت سرور
│   ├── app.ts            ← سرهم‌کردن قطعات (مسیرها، CORS، ...)
│   ├── env.ts            ← 📌 لیست همه تنظیمات محیطی
│   ├── db/               ← دیتابیس سرور (جدول‌ها)
│   ├── routes/           ← آدرس‌های API (هر فایل = یک گروه آدرس)
│   ├── services/         ← منطق اصلی (قیمت، اشتراک، کد پیامکی، توکن)
│   ├── providers/        ← اتصال به سرویس‌های بیرونی (پیامک، درگاه)
│   ├── plugins/          ← احراز هویت + مدیریت خطا
│   └── lib/phone.ts      ← ⚠️ قل دومِ استانداردسازی شماره (باید با فرانت یکی باشه)
├── test/                 ← تست‌های خودکار
├── .pglite-data/         ← 💾 دیتابیس توسعه (فایل‌های دیتا — پاکش کنی همه‌چی صفر می‌شه)
└── package.json          ← دستورها: dev, build, start, test
```

## ۲. استارت و تنظیمات

### `backend/src/index.ts` — نقطه شروع
تنها جایی که اتصال واقعی دیتابیس ساخته می‌شه. با توجه به env تصمیم می‌گیره:
- **دیتابیس:** `DB_DRIVER=pglite` (پیش‌فرض توسعه — پستگرس واقعی ولی داخل خود پروسه، بدون نصب هیچی، دیتا در `.pglite-data/`) یا `postgres` (پروداکشن)
- **پیامک:** `SMS_PROVIDER=console` (چاپ کد در ترمینال) یا `kavenegar` (ارسال واقعی)
- **درگاه:** `PSP_PROVIDER=fake` (درگاه تقلبی تست) یا `zibal` (واقعی)

موقع بالا آمدن: جدول‌ها رو می‌سازه (اگه نباشن)، پلن‌ها رو seed می‌کنه، و هر ۱ ساعت کدهای پیامکی قدیمی‌تر از ۲۴ ساعت رو پاک می‌کنه.

### `backend/src/env.ts` — 📌 همه‌ی تنظیمات محیطی در یک نگاه

| متغیر | پیش‌فرض | یعنی |
|---|---|---|
| `PORT` | `3000` | پورت سرور |
| `DB_DRIVER` | `pglite` | نوع دیتابیس (پروداکشن: اجباراً `postgres`) |
| `DATABASE_URL` | `postgres://routino:routino@localhost:5432/routino` | آدرس پستگرس واقعی |
| `CORS_ORIGINS` | لوکال‌ها + `https://localhost` + `capacitor://localhost` | ⚠️ کدوم آدرس‌ها اجازه دارن به API وصل شن — دو تای آخر برای اپ موبایل **حیاتی**اند |
| `TRUST_PROXY` | `false` | فقط وقتی پشت پروکسی (Caddy/Nginx) هستی `true` کن — وگرنه هرکسی می‌تونه IP جعل کنه و از سقف پیامک رد شه |
| `ADMIN_TOKEN` | `dev-only-admin-token` | 🔑 رمز پنل ادمین (حداقل ۱۲ کاراکتر) |
| `JWT_SECRET` | dev-only... | کلید امضای توکن ورود (حداقل ۳۲ کاراکتر) |
| `ACCESS_TTL_SECONDS` | `900` | عمر توکن دسترسی (۱۵ دقیقه) |
| `REFRESH_TTL_DAYS` | `180` | عمر توکن تمدید (۶ ماه = کاربر چقدر بدون ورود مجدد می‌مونه) |
| `OTP_PEPPER` | dev-only... | نمک مخفی هش کدهای پیامکی |
| `OTP_TTL_SECONDS` | `120` | اعتبار کد پیامکی (۲ دقیقه) |
| `OTP_MAX_ATTEMPTS` | `5` | حداکثر حدس اشتباه برای هر کد |
| `SMS_PROVIDER` | `console` | `console` یا `kavenegar` |
| `KAVENEGAR_API_KEY` | — | کلید API کاوه‌نگار |
| `KAVENEGAR_TEMPLATE` | `routino-otp` | اسم قالب تاییدشده در پنل کاوه‌نگار |
| `PSP_PROVIDER` | `fake` | یک درگاه: `fake` / `zibal` / `zarinpal` |
| `PSP_PROVIDERS` | — | چند درگاه با کاما، مثل `zarinpal,zibal` (سرور سریع‌ترین سالم رو انتخاب می‌کنه + جایگزینی خودکار). اگه پر باشه جای `PSP_PROVIDER` رو می‌گیره |
| `ZIBAL_MERCHANT` | `zibal` | مرچنت زیبال (کلمه‌ی `zibal` = حالت سندباکس) |
| `ZARINPAL_MERCHANT` | — | مرچنت زرین‌پال (۳۶ نویسه؛ فقط وقتی زرین‌پال فعاله) |
| `PUBLIC_API_URL` | `http://localhost:3000` | آدرس عمومی همین سرور (درگاه، مرورگرِ کاربر رو به اینجا برمی‌گردونه — از گوشی باید قابل دسترس باشه) |
| `PUBLIC_WEB_URL` | `http://localhost:5180` | آدرس نسخه وب اپ (برای برگشت بعد از پرداخت وب) |
| `APP_DEEP_LINK` | `routino://pay/result` | لینک برگشت به اپ موبایل بعد از پرداخت |
| `IMPORT_MAX_DAYS` | `400` | سقف روزهای قابل قبول موقع انتقال اشتراک قدیمی |

**محافظ‌های پروداکشن (خودکار):** اگه `NODE_ENV=production` باشه و secretها `dev-only` مونده باشن، یا `PSP_PROVIDER=fake` باشه، یا `DB_DRIVER=pglite` باشه → سرور **اصلاً بالا نمیاد**. این عمدیه که با تنظیمات تستی نری روی هوا.

### `backend/src/app.ts` — سرهم‌کننده
Fastify رو می‌سازه، CORS و فشرده‌سازی و helmet رو فعال می‌کنه، مدیریت خطا و پلاگین احراز هویت رو ثبت می‌کنه، و همه‌ی گروه‌های مسیر رو با پیشوند `/v1` رجیستر می‌کنه. هیچ اتصال دیتابیسی اینجا ساخته نمی‌شه (تزریق می‌شه) — همینه که تست‌ها بدون داکر اجرا می‌شن.

## ۳. دیتابیس سرور — پوشه `backend/src/db/`

### `backend/src/db/schema.ts` — جدول‌ها به زبان ساده

| جدول | چی توشه | نکته مهم |
|---|---|---|
| `users` | کاربرها: شماره موبایل استاندارد (`989...`)، بلاک‌بودن، شمارنده سینک (`seq`) | شماره unique است — دو حساب با یک شماره غیرممکنه |
| `records` | 📦 دیتای سینک‌شونده کاربر (عادت‌ها، لاگ‌ها، ...) به شکل عمومی JSON — **برای سینکِ آینده؛ الان هنوز استفاده نمی‌شه** | یک جدول برای همه نوع رکورد؛ فیلد جدید عادت = بدون تغییر سرور |
| `devices` | دستگاه‌های هر کاربر + هَشِ توکن تمدید | خود توکن هیچ‌وقت ذخیره نمی‌شه، فقط هَشش |
| `otp_codes` | کدهای پیامکی (هش‌شده) + شمارنده تلاش | همین جدول دفترِ سقف ارسال هم هست |
| `plans` | 💰 پلن‌های فروش: `m1`/`m3`/`m12` با قیمت تومان | قیمت واقعی اپ اینجاست — تغییر قیمت = آپدیت این جدول |
| `discounts` | کدهای تخفیف: درصد، سقف استفاده، انقضا، محدود به یک شماره | |
| `redemptions` | کی از چه کدی استفاده کرده | هر کاربر هر کد فقط ۱ بار (کلید ترکیبی) |
| `payments` | 💳 هر تراکنش: مبلغ (تومان و ریال)، وضعیت (`pending/redirected/paid/failed/canceled/verify_failed`)، شماره پیگیری درگاه، پلتفرم (web/android/ios)، و **`applied_at`** | `applied_at` = قفل ضد دوباره‌شارژ شدن |
| `grants` | 📒 **دفترکل اشتراک** — هر تمدید یک سطر: از کجا (تریال/پرداخت/انتقال/ادمین)، چند ماه/روز، انقضای قبل و بعد | هیچ‌وقت ویرایش/حذف نمی‌شه. جواب «پول دادم فعال نشد» همیشه اینجاست |
| `entitlements` | جواب فعلی: «این کاربر تا فلان تاریخ دسترسی داره» | فقط `services/entitlement.ts` حق نوشتن توش داره |
| `feedback` | نظرسنجی‌های کاربرها | |
| `admins` | (رزرو آینده) | |

### دو فایل دیگر

| آدرس | نقش |
|---|---|
| `backend/src/db/ddl.ts` | SQL ساخت جدول‌ها + **`SEED_PLANS_SQL`** (قیمت اولیه: یک‌ماهه ۵۹٬۰۰۰ / سه‌ماهه ۱۴۹٬۰۰۰ / یک‌ساله ۴۴۹٬۰۰۰ تومان — فقط برای نصب اول؛ بعدش قیمت از خود جدول خونده می‌شه) + کد تخفیف تستی `ROUTINO20` (۲۰٪ — به پروداکشن نمی‌ره) |
| `backend/src/db/client.ts` | تایپ مشترک دیتابیس (پستگرس واقعی و PGlite) + تابع `rowsOf` برای SQL خام — دست نزن |

## ۴. مسیرهای API — پوشه `backend/src/routes/`

### `backend/src/routes/auth.ts` — ورود با پیامک

| متد و آدرس | ورودی | چیکار می‌کنه |
|---|---|---|
| `POST /v1/auth/otp/request` | `{phone}` | چک سقف ارسال ← ساخت کد ۶ رقمی ← ارسال پیامک. جوابش برای شماره‌ی موجود و ناموجود یکسانه (که نشه فهمید کی عضو روتینوئه) |
| `POST /v1/auth/otp/verify` | `{phone, code, deviceName}` | چک کد ← اگه کاربر جدیده: ساخت حساب + **۷ روز هدیه** (ثابت `TRIAL_DAYS = 7` بالای همین فایل) ← صدور توکن‌ها + وضعیت اشتراک |
| `POST /v1/auth/token/refresh` | `{refresh}` | توکن تازه می‌ده؛ توکن قبلی همون لحظه می‌میره |
| `POST /v1/auth/logout` | `{refresh}` | خروج این دستگاه (توکن ناشناس هم ۲۰۰ می‌گیره — بی‌ضرره) |

### `backend/src/routes/payments.ts` — 💳 مسیر پول (⚠️ حساس‌ترین فایل بک‌اند)

| متد و آدرس | چیکار می‌کنه |
|---|---|
| `POST /v1/payments/quote` | پیش‌فاکتور: قیمت پایه + بررسی کد تخفیف. کد نامعتبر = «دلیل» برمی‌گرده نه خطا (که UI پیام درست نشون بده) |
| `POST /v1/payments/checkout` | ساخت سطر پرداخت (مبلغ **سمت سرور** حساب می‌شه) ← ثبت در درگاه ← برگردوندن `paymentUrl`. سقف ۱۰ خرید در ساعت برای هر کاربر. تخفیف ۱۰۰٪ = بدون درگاه، مستقیم فعال می‌شه |
| `GET /v1/payments/callback` | 🌐 مرورگرِ کاربر بعد از درگاه به اینجا برمی‌گرده. `success=1` توی آدرس **هیچ ارزشی نداره** (هرکی می‌تونه تایپش کنه) — تایید واقعی فقط با تماس سرور-به-سرور (`psp.verify`) انجام می‌شه و **مبلغِ تاییدشده باید دقیقاً با مبلغ ما برابر باشه** وگرنه `verify_failed` + لاگ اضطراری. بعدش صفحه HTML نتیجه رو نشون می‌ده (`sendResultPage` — پایین همین فایل) که کاربر رو به وب یا دیپ‌لینک اپ برمی‌گردونه |
| `GET /v1/payments/:id` | استعلام وضعیت برای اپ. **خود-درمانی:** اگه پرداختی در حالت `redirected` گیر کرده (callback هیچ‌وقت نرسیده)، همین‌جا دوباره از درگاه استعلام و در صورت موفقیت فعال می‌شه |

**قفل ضد دوباره‌شارژ (`applyPaid`):** فعال‌سازی فقط با `UPDATE ... WHERE applied_at IS NULL` انجام می‌شه — یعنی حتی اگه درگاه ۱۰ بار callback بزنه یا کاربر ۱۰ بار رفرش کنه، اشتراک فقط **یک بار** اضافه می‌شه. اگه وسط کار خطا بخوره، قفل آزاد می‌شه که تلاش بعدی جبران کنه (پولِ داده‌شده هیچ‌وقت نباید بسوزه).

### `backend/src/routes/subscriptions.ts` — اشتراک

| متد و آدرس | چیکار می‌کنه |
|---|---|
| `GET /v1/subscriptions/me` | «تا کِی دسترسی دارم؟» — فرانت اول هر اجرا اینو می‌پرسه |
| `POST /v1/subscriptions/import` | انتقال یک‌باره‌ی اشتراک قدیمیِ محلی به سرور. چون ادعای کلاینته قابل اعتماد نیست، **محدود** می‌شه: فقط یک بار در عمر حساب، حداکثر `IMPORT_MAX_DAYS` (۴۰۰ روز)، فقط بالا بردن انقضا (نه جمع‌زدن)، و ادعای خام برای حسابرسی ثبت می‌شه |
| `GET /v1/subscriptions/grants` | کل دفترکل تمدیدهای این کاربر (برای پشتیبانی) |

### بقیه‌ی مسیرها

| آدرس فایل | آدرس‌های API | نقش |
|---|---|---|
| `backend/src/routes/plans.ts` | `GET /v1/plans` | عمومی — لیست پلن‌های فعال با قیمت (فرانت صفحه اشتراک از این می‌خونه) |
| `backend/src/routes/admin.ts` | `GET /v1/admin/overview`، `GET/POST /v1/admin/users...`، `POST .../block`، `POST .../grant`، `GET /v1/admin/payments`، `GET/POST /v1/admin/discounts...` | API ادمین: آمار کلی (کاربر/درآمد/OTP)، جستجوی کاربر با شماره، مشاهده جزئیات (دستگاه‌ها/پرداخت‌ها/گرنت‌ها)، بلاک (نشست‌ها هم قطع می‌شن)، هدیه اشتراک، مدیریت کدهای تخفیف. احراز: هدر `x-admin-token` |
| `backend/src/routes/admin-panel.ts` | `GET /admin` | 🖥️ **پنل ادمین** — یک صفحه HTML کامل (بدون فریم‌ورک) که با همون APIهای بالا کار می‌کنه. ظاهر، متن‌ها و تب‌های پنل همه داخل همین فایل‌اند |
| `backend/src/routes/dev-gateway.ts` | `GET /v1/dev/gateway` | درگاه تقلبی تست: صفحه «پرداخت موفق / انصراف». فقط وقتی `PSP_PROVIDER=fake` فعاله |
| `backend/src/routes/health.ts` | `GET /health`، `GET /health/ready` | چک سلامت (دومی دیتابیس رو هم تست می‌کنه — مناسب مانیتورینگ) |

## ۵. منطق اصلی — پوشه `backend/src/services/`

### `backend/src/services/entitlement.ts` — حساب‌وکتاب اشتراک
- `readEntitlement` — جواب فعلی: `active` / `expired` / `none` + تاریخ انقضا
- `grantInterval` — تمدید با **ماه تقویمی واقعی** (پستگرس حساب می‌کنه؛ «یک سال» = ۱۲ ماه واقعی نه ۳۶۰ روز). اگه اشتراک هنوز فعاله، از انتهای همون ادامه می‌ده (زودتر خریدن = روز نمی‌سوزه). هر تمدید یک سطر در دفترکل `grants` ثبت می‌کنه
- `ensureExpiresAt` — مخصوص انتقال اشتراک قدیمی: فقط «بالا می‌بره تا»، هیچ‌وقت جمع نمی‌زنه
- `hasSettledGrant` — «این حساب قبلاً پرداخت یا انتقال داشته؟» (قفل تکرار import)

### `backend/src/services/pricing.ts` — قیمت
- `quote` — قیمت نهایی: پایه ← اِعمال آفر ← اِعمال تخفیف ← گرد کردن. تبدیل تومان→ریال (×۱۰) **فقط همین‌جاست**
- `checkDiscount` — همه دلایل رد کد: ناشناخته/غیرفعال/منقضی/ظرفیت‌تمام/مال یکی دیگه/قبلاً استفاده‌شده
- `redeemDiscount` — مصرف کد؛ فقط **بعد از** موفقیت پرداخت صدا زده می‌شه (خرید نصفه‌کاره کد رو نمی‌سوزونه)

### `backend/src/services/otp.ts` — کدهای پیامکی
- کد: ۶ رقمی از مولد امن؛ فقط هَشِ نمک‌دارش ذخیره می‌شه؛ ۲ دقیقه اعتبار؛ ۵ حدس؛ فقط جدیدترین کد معتبره (درخواست کد جدید = ابطال قبلی)
- 💸 **سقف‌های ارسال (`LIMITS`)** — هر پیامک پول واقعیه:

| سقف | مقدار |
|---|---|
| هر شماره در دقیقه | ۱ |
| هر شماره در ساعت | ۵ |
| هر شماره در روز | ۱۰ |
| هر IP در ساعت | ۲۰ |
| کل سیستم در روز | ۲۰۰۰ (کلید قطع اضطراری — اگه خورد یعنی یه اتفاق غیرعادی افتاده) |

### `backend/src/services/tokens.ts` — توکن‌ها
- **Access:** JWT امضاشده، ۱۵ دقیقه، بدون مراجعه به دیتابیس چک می‌شه
- **Refresh:** رشته تصادفی مات، ۱۸۰ روز، با هر استفاده **عوض می‌شه** (قبلی می‌میره)، قابل ابطال (بلاک کاربر = ابطال همه دستگاه‌ها با `revokeAllDevices`)

## ۶. سرویس‌های بیرونی — پوشه `backend/src/providers/`

| آدرس | نقش | نکته |
|---|---|---|
| `providers/sms/console.ts` | چاپ کد در ترمینال سرور (توسعه) | خط `[sms:console] OTP for 989... -> 123456` |
| `providers/sms/kavenegar.ts` | ارسال واقعی با کاوه‌نگار (مسیر `verify/lookup`) | ⚠️ قالب پیامک باید قبلاً در پنل کاوه‌نگار **تایید** شده باشه (چند روز طول می‌کشه — زودتر اقدام کن) |
| `providers/psp/index.ts` | قرارداد مشترک درگاه (`PspProvider`) + قرارداد روتر (`PspRouter`) + جدول کدهای «متعارف» (`ZIBAL_RESULT`: ۱۰۰=موفق، ۲۰۱=قبلاً تاییدشده / `ZIBAL_STATUS`: ۱=پرداخت تایید، ۳=لغو کاربر، ...) | همه‌ی درگاه‌ها کدشون رو به همین کدها ترجمه می‌کنن |
| `providers/psp/zibal.ts` | درگاه واقعی زیبال: `request` (ثبت)، `verify` (تایید سرور-به-سرور)، `startUrl` (آدرس صفحه پرداخت) | مرچنت `"zibal"` = سندباکس رایگان |
| `providers/psp/zarinpal.ts` | درگاه واقعی زرین‌پال (REST v4). توکن تراکنش یک رشته‌ی `authority`ه (نه عدد)؛ مبلغ ریالی با `currency:"IRR"` | کدهای زرین‌پال رو به کدهای متعارف ترجمه می‌کنه |
| `providers/psp/fake.ts` | درگاه تقلبی حافظه‌ای — همون قرارداد زیبال، بدون پول واقعی | کل ماشین پرداخت باهاش تست می‌شه |
| `providers/psp/router.ts` | روتر چند-درگاهه: سریع‌ترین سالم رو (از روی زمان پاسخ واقعی) انتخاب می‌کنه + جایگزینی خودکار. با یک درگاه فقط رد می‌کنه | درگاهِ هر پرداخت روی سطرش ذخیره میشه تا verify درست برگرده |

## ۷. احراز هویت و خطاها — پوشه `backend/src/plugins/`

| آدرس | نقش |
|---|---|
| `plugins/auth.ts` | نگهبان مسیرهای خصوصی: هدر `Authorization: Bearer ...` رو چک می‌کنه. هر بار کاربر رو از دیتابیس هم می‌خونه — به همین دلیل «بلاک» حداکثر ۱۵ دقیقه بعد اثر می‌کنه، نه هر وقت توکن مُرد |

## ۱۰. ⚠️ چیزهایی که در بک‌اند دست نزنی مگر با فهم کامل

1. **`routes/payments.ts`** — منطق `applied_at` و مقایسه مبلغ. جابه‌جایی یک شرط = یا دوباره‌شارژ مفتی یا سوختن پول کاربر.
2. **`lib/phone.ts`** — باید بایت‌به‌بایت با `src/lib/phone.ts` فرانت یکی بمونه (تست parity داره).
3. **`services/entitlement.ts`** — تنها نویسنده‌ی `entitlements`؛ دفترکل `grants` هیچ‌وقت ویرایش نمی‌شه.
4. **ترتیب چک‌ها در `services/otp.ts`** — «تلاش قبل از مقایسه شمرده می‌شه» عمدیه (کرش وسط کار = حدس مفتی نده).
5. **`env.ts` محافظ‌های production** — حذفشون نکن؛ همونان که نمی‌ذارن با تنظیمات تستی لایو بری.
