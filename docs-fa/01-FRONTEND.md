# 🎨 راهنمای کامل فرانت‌اند روتینو

> **فرانت‌اند یعنی چی؟** هر چیزی که کاربر می‌بینه و لمس می‌کنه: صفحه‌ها، دکمه‌ها، رنگ‌ها، انیمیشن‌ها، و دیتابیس محلیِ داخل خود گوشی/مرورگر.
> همه‌ی فرانت داخل پوشه‌ی **`src/`** است + چند فایل تنظیمات در ریشه‌ی پروژه.
>
> این فایل مکمل [CODEBASE_GUIDE.md](CODEBASE_GUIDE.md) است — اونجا نقشه‌ی کلی و «دستور پخت‌ها» رو داری؛ اینجا جزئیات کامل هر فایل فرانت.

---

## ۱. نقشه پوشه‌ی `src/`

```
src/
├── client.tsx            ← روشن‌شدن اپ (نقطه استارت)
├── routeTree.gen.ts      ← ⛔ تولید خودکار — هرگز دستی ویرایش نکن
├── styles.css            ← 🎨 همه رنگ‌ها و تم روشن/تیره
├── routes/               ← 📱 صفحه‌های اپ (هر فایل = یک صفحه)
├── components/           ← 🧩 قطعه‌های تکرارشونده (کارت عادت، فرم، منو...)
├── state/                ← 🧠 مغز اپ (فقط یک فایل: app.tsx)
├── lib/                  ← ⚙️ منطق و محاسبات (بدون ظاهر)
│   ├── db/               ← 💾 ذخیره‌سازی محلی
│   └── api/              ← 🌐 ارتباط با سرور
└── test/                 ← تنظیمات تست‌ها
```

## ۲. نقطه شروع اپ — چطور روشن می‌شه؟

| آدرس فایل | نقش | توضیح ساده |
|---|---|---|
| `index.html` | صفحه پایه | تنها فایل HTML واقعی. عنوان تب مرورگر، لود فونت وزیرمتن، و `<div id="root">` که کل اپ داخلش رندر می‌شه |
| `src/client.tsx` | استارتر | ۱) روتر رو می‌سازه ۲) PWA رو راه می‌ندازه (`initPwa`) ۳) روی موبایل به دیپ‌لینک `routino://pay/result` گوش می‌ده (بازگشت از درگاه پرداخت) ۴) اپ رو رندر می‌کنه |
| `src/routes/__root.tsx` | قالب سراسری | دور همه‌ی صفحه‌ها می‌پیچه: `AppProvider` (مغز اپ)، `Toaster` (پیام‌های کوچک پایین صفحه)، `UpdateWatcher` (اعلان نسخه جدید)، صفحه ۴۰۴ و صفحه خطا |
| `src/routeTree.gen.ts` | ⛔ خودکار | با هر بار اجرای dev/build از روی پوشه `routes/` ساخته می‌شه. آدرس صفحه‌ها از اسم فایل‌ها میاد (مثلاً `habits.tsx` → آدرس `/habits`) |

**زنجیره‌ی روشن‌شدن:** `index.html` ← `client.tsx` ← `__root.tsx` ← `AppProvider` (لود دیتا) ← `AppShell` (چک گِیت) ← صفحه‌ی مقصد

## ۳. مغز اپ — `src/state/app.tsx` (مهم‌ترین فایل فرانت)

این فایل «AppProvider» رو تعریف می‌کنه که همه‌ی صفحه‌ها ازش تغذیه می‌شن. هر صفحه با `useApp()` یا `useAppMaybe()` به این ۵ چیز دسترسی داره:

| چیز | یعنی |
|---|---|
| `db` | کل دیتای اپ در حافظه (عادت‌ها، کارها، ژورنال، تنظیمات...) — شکلش در `lib/store.ts` تعریف شده |
| `update(fn)` | **تنها راه تغییر دیتا.** یه تابع می‌گیره که db قدیمی رو می‌گیره و db جدید برمی‌گردونه |
| `lang` / `cal` | زبان فعلی (`fa`/`en`) و تقویم فعلی (`jalali`/`gregorian`) |
| `t(fa, en)` | تابع ترجمه: اگه زبان فارسیه متن اول، وگرنه متن دوم |

**کارهایی که این فایل خودکار انجام می‌ده (به ترتیب داخل فایل):**

1. **لود اولیه (hydrate):** موقع باز شدن اپ، دیتا رو از دیسک می‌خونه + شمارنده جلسات (`sessions`) رو یکی زیاد می‌کنه + دستکاری ساعت رو چک می‌کنه.
2. **ذخیره خودکار:** بعد از هر `update`، تغییرها رو تشخیص می‌ده و در پس‌زمینه ذخیره می‌کنه — UI هیچ‌وقت منتظر ذخیره نمی‌مونه (به همین دلیل آفلاین و آنلاین فرقی حس نمی‌شه).
3. **تازه‌سازی اشتراک:** یک بار در هر اجرا، از سرور می‌پرسه «اشتراک این کاربر تا کِیه؟» و جواب رو در `db.subscription` کش می‌کنه. اگه آفلاین باشه، بی‌صدا رد می‌شه.
4. **ضربان‌سنج (heartbeat):** هر ۶۰ ثانیه `lastSeen` رو به‌روز می‌کنه. اگه ساعت دستگاه بیش از **۶ ساعت** (`TAMPER_TOLERANCE`) به عقب کشیده بشه → `tampered = true` → اشتراک قفل می‌شه تا تمدید کنه. (قبلاً ۵ دقیقه بود؛ گوشی‌ای که مدتی خاموش یا بی‌آنتن بوده موقع تصحیح خودکار ساعت بیشتر از این جابه‌جا می‌شه و بی‌گناه قفل می‌شد. برای کش‌رفتن اشتراک باید ساعت روزها عقب بره که همچنان گرفته می‌شه.) پاک‌شدن این پرچم فقط با جواب سرور ممکنه — و اون درخواست حالا در صورت شکست هر ۶۰ ثانیه دوباره تلاش می‌کنه.
5. **اعمال تم/زبان/رنگ:** کلاس `dark`، جهت `rtl/ltr`، و متغیر CSS `--primary` (رنگ برند) رو روی صفحه می‌ذاره.
6. **یادآورهای نیتیو:** روی موبایل، آلارم‌های سیستم‌عامل رو با دیتا سینک می‌کنه (`syncRecurringReminders`).
7. **یادآور داخل اپ:** هر ۳۰ ثانیه چک می‌کنه: عادتی که ساعت یادآورش الانه؟ کاری که یادآورش رسیده؟ ساعت ژورنال شده؟ → اعلان می‌سازه (متن اعلان‌ها همین‌جاست).

## ۴. منطق و محاسبات — پوشه `src/lib/`

### `src/lib/store.ts` — «فرهنگ لغت» دیتا
تعریف اینکه هر موجودیت چه فیلدهایی داره. اگه بخوای بدونی «عادت چیا داره؟» جواب اینجاست:

| موجودیت | فیلدهای مهم |
|---|---|
| `Settings` | زبان، تقویم، تم، رنگ برند، `onboarded`، ساعت یادآور ژورنال (پیش‌فرض `22:00`)، روشن‌بودن نوتیف |
| `Habit` (عادت) | اسم، دسته، نوع (`binary`=شد/نشد یا `quantity`=مقداری)، هدف (`target` — برای عادت زمانی = کل دقیقه)، واحد، برنامه هفتگی (`schedule`)، هدف ماهانه، ساعت یادآور، تاریخ ساخت |
| `HabitLog` (ثبت روزانه) | کلیدش `habitId|تاریخ` است؛ مقدار، انجام‌شده، یادداشت، حس‌وحال |
| `Task` (کار) | تاریخ، عنوان، نوع، هدف/مقدار، یادداشت، ساعت یادآور، رنگ، آیکون |
| `TimerSession` | حالت تایمر، ثانیه‌های تمرکز، شروع/پایان، اتصال به عادت/کار |
| `JournalEntry` | متن، نمره ۱–۱۰، حس‌وحال، به کلید تاریخ |
| `Subscription` | پلن، شروع، انقضا (`expiresAt`)، آزمایشی بودن |
| `meta` | شمارنده جلسات، آخرین نظرسنجی، `lastSeen` و `tampered` (ضد دستکاری ساعت)، جشن‌های داده‌شده، یادآورهای شلیک‌شده |

همین‌جا: `uid()` (تولید شناسه تصادفی) و `defaultDb()` (دیتای کاربر تازه‌وارد).

### `src/lib/logic.ts` — ماشین‌حساب اپ
همه‌ی فرمول‌ها، بدون هیچ ظاهری:

| تابع | چیکار می‌کنه |
|---|---|
| `isDueOn(habit, روز)` | «این عادت امروز فعاله؟» (روزانه/زوج/فرد/روزهای خاص هفته + قبل از تاریخ ساخت هیچ‌وقت) |
| `rawPercent` / `cappedPercent` | درصد انجام یک روز (خام می‌تونه از ۱۰۰ رد بشه، سقف‌دار نه) |
| `isCompleted` | انجام‌شده حساب می‌شه؟ (برای مقداری: رسیدن به هدف هم کافیه) |
| `dayScore` | نمره کل روز = میانگین درصد عادت‌های فعال اون روز |
| `streak` 🔥 | چند روزِ فعالِ پشت‌سرهم انجام شده (اگه امروز هنوز نه، از دیروز می‌شمره؛ حداکثر ۷۳۰ روز عقب می‌ره) |
| `monthProgress` | پیشرفت به سمت هدف ماهانه (روزهای انجام‌شده / هدف) |
| `earnedBadges` 🏅 | همه نشان‌ها — از روی خودِ لاگ‌ها حساب می‌شه (نه ذخیره)، پس هیچ‌وقت غلط نمی‌مونه |
| `successRate` | درصد موفقیت N روز اخیر |
| `habitSeries` / `overallSeries` / `weekComparison` | داده‌های خام نمودارها |
| `subscriptionActive` 🔑 | «اشتراک فعاله؟» — اگه `tampered` باشه همیشه «نه» |

### `src/lib/dates.ts` — تقویم و تاریخ
تبدیل شمسی↔میلادی (کتابخانه jalaali-js)، کلید تاریخ (`YYYY-MM-DD` همیشه میلادی)، اسم ماه‌ها و روزها (فارسی/انگلیسی + کوتاه‌شده)، شروع هفته (شنبه برای شمسی، یکشنبه برای میلادی)، عدد فارسی‌کن (`faNum`)، فرمت‌های نمایش تاریخ، و بازه‌های نمودار آنالیز (`analyticsDayKeys`: هفته=۷ روز اخیر، ماه=۳۱، سه‌ماهه=۹۱، سال=۱۲ ماه تقویمی).

### `src/lib/presets.ts` — محتوای آماده
- `DEFAULT_CATEGORIES` — ۱۶ دسته پیش‌فرض (صبحگاهی، سلامتی، ورزش، ... ، محدودیت‌ها) با رنگ و آیکون
- `PRESET_HABITS` — عادت‌های آماده‌ی هر دسته (نام فارسی/انگلیسی، نوع، هدف، واحد)
- `PLANS` — نسخه‌ی آفلاین قیمت پلن‌ها (باید با سرور یکی باشه — فایل ۰۳ رو ببین)
- `CATEGORY_COLOR_CHOICES` — ۲۰ رنگ قابل انتخاب
- `MOOD_EMOJIS` — ۱۰ ایموجی حس‌وحال

## ۵. ذخیره‌سازی محلی — پوشه `src/lib/db/` ⚠️ منطقه حساس

دیتا **داخل خود دستگاه** ذخیره می‌شه (IndexedDB مرورگر/WebView). اینترنت لازم نیست.

| آدرس | نقش | توضیح ساده |
|---|---|---|
| `src/lib/db/dexie.ts` | تعریف جدول‌ها | ۸ جدول: categories, habits, logs, tasks, timerSessions, journal, settings, feedback. هر رکورد یه «پاکت» داره: `updatedAt` (زمان تغییر)، `deleted` (سنگ‌قبر حذف)، `dirty` (منتظر ارسال به سرور — برای سینک آینده)، `seq` (حفظ ترتیب نمایش) |
| `src/lib/db/local.ts` | چیزهای مخصوصِ این دستگاه | در localStorage (`routino:local:v1`): ورود، اشتراکِ کش‌شده، اعلان‌ها، meta، تم، نوتیف. دو لیست مهم: `SYNCED_SETTING_KEYS` (تنظیماتی که بین دستگاه‌ها مشترک می‌شن: زبان، تقویم، رنگ برند، onboarded، ساعت ژورنال) و `LOCAL_SETTING_KEYS` (مخصوص دستگاه: تم، نوتیف) |
| `src/lib/db/hydrate.ts` | خوندن موقع استارت | همه جدول‌ها رو می‌خونه و شیء `Db` رو می‌سازه. برای نصب تازه، ۱۶ دسته پیش‌فرض رو می‌کاره (`seedIfEmpty`) |
| `src/lib/db/diff.ts` | تشخیص تغییر | **حساس‌ترین فایل ذخیره‌سازی.** با مقایسه‌ی مرجع (reference) می‌فهمه دقیقاً کدوم رکوردها عوض شدن — چیزی که اینجا جا بیفته، هیچ‌وقت ذخیره نمی‌شه |
| `src/lib/db/persist.ts` | نوشتن روی دیسک | تغییرها رو در یک تراکنش می‌نویسه؛ حذف = رکورد سنگ‌قبر (نه پاک‌شدن کامل). تابع `pendingChanges` = صف ارسال برای سینک آینده |
| `src/lib/db/migrate.ts` | مهاجرت نسخه قدیمی | دیتای فرمت قدیمی (`routino:v1` در localStorage) رو یک بار به IndexedDB منتقل می‌کنه. **نسخه قدیمی عمداً پاک نمی‌شه** (بیمه‌ی بازیابی) |

## ۷. صفحه‌های اپ — پوشه `src/routes/`

> قانون: اسم فایل = آدرس صفحه. `index.tsx`=`/`، `habits.tsx`=`/habits`، `habit.$habitId.tsx`=`/habit/یک-شناسه`، `pay.result.tsx`=`/pay/result`

### `src/routes/index.tsx` — صفحه «امروز»
- سلامِ ساعتی (صبح/ظهر/عصر بخیر — متنش همین‌جاست) + تاریخ امروز
- حلقه‌ی درصد روز (انیمیشن پرشدن از صفر) — از `dayScore` تغذیه می‌شه
- نوار هفته (`WeekStrip`) با تعداد عادت‌های هر روز و حلقه درصد
- کارت «کارها» (از `components/tasks.tsx`) + لیست عادت‌های فعالِ روزِ انتخابی (`HabitRow`)
- پاپ‌آپ جشن وقتی به ۷۰٪ یا ۱۰۰٪ هدف ماهانه برسی

### `src/routes/habits.tsx` — مدیریت عادت‌ها
- دو دکمه بالا: «عادت‌های آماده» (مودال پیشنهادها) و «عادت دلخواه» (فرم خالی)
- نوار فیلتر: همه / انجام‌نشده / انجام‌شده / دسته‌ها (فقط دسته‌هایی که عادت دارن) / + دسته جدید

- تابع `completeLogin()` مشترک بین هر دو روش: انتقال اشتراک قدیمیِ محلی (`importSubscription`) + `loginAs` (جداسازی حساب بر اساس شماره‌ی سرور `res.user.phone`)

- ⚠️ یک پرچم تستی مونده: `SKIP_SMS` — الان `false`ه و باید `false` بمونه (دکمه‌ی `TEST_LOGIN_BUTTON` حذف شد)

### `src/routes/subscribe.tsx` — دیوار اشتراک (پی‌وال)
- لیست پلن‌ها از سرور (`fetchPlans`)؛ اگه سرور در دسترس نبود از نسخه آفلاین (`FALLBACK_PLANS`) فقط برای **نمایش** استفاده می‌کنه — خرید حتماً اینترنت می‌خواد

- ⚠️ پرچم تستی: `TEST_GRANT_BUTTON` (تمدید بدون پرداخت، فقط محلی) — الان از قبل `false` است؛ اگه روشنش کردی قبل از انتشار برگردون

### `src/routes/pay.result.tsx` — نتیجه پرداخت
بعد از برگشت از درگاه اینجا فرود میای (`?paymentId=…&status=…`). وضعیت واقعی رو از سرور می‌پرسه و اگه هنوز نامشخصه هر ۲.۵ ثانیه دوباره می‌پرسه (حداکثر ~۱ دقیقه). اگه «paid» بود، اشتراک محلی آپدیت می‌شه و گِیت باز می‌شه. ۴ حالت نمایش: موفق 🎉 / لغوشده / ناموفق / هنوز نرسیده.

### قوانین و مقررات / حریم خصوصی / تماس — داخل تنظیمات
برای **اینماد** لازم بود. کلِّ متن (قوانین و مقررات + حریم خصوصی + تماس با ما) در یک **بخش بازشوی واحد** داخل صفحه‌ی تنظیمات (`routes/settings.tsx`) نمایش داده می‌شود — کامپوننت [`src/components/LegalContent.tsx`](../src/components/LegalContent.tsx). عمداً صفحه‌ی جدا یا لینکِ صفحه‌ی اول **ندارد** (به‌خواست مالک؛ روش تأیید اینمادش فرق داشت). اطلاعات تماس/هویتی از [`src/lib/legal-info.ts`](../src/lib/legal-info.ts) می‌آید — **فقط همان ۴ مقدار (نام مالک، تلفن، ایمیل، نشانی) را باید پر کنی**. دوزبانه؛ اگر کانتکست آماده نباشد فارسی پیش‌فرض است.

## ۱۱. الگوهایی که همه‌جای فرانت تکرار می‌شن (یاد بگیری، همه‌جا رو می‌فهمی)

1. **دوزبانه:** هر متن به شکل `t("متن فارسی", "English text")` — برای عوض‌کردن متن، همون صفحه رو باز کن و متن فارسی رو جستجو کن.
2. **تغییر دیتا:** همیشه `update((d) => ({ ...d, چیزِ‌جدید }))` — هیچ‌وقت مستقیم چیزی تغییر نمی‌کنه؛ نسخه‌ی جدید ساخته می‌شه (این چیزیه که ذخیره‌ی خودکار بهش وابسته‌ست).
3. **کلید تاریخ:** روزها همیشه رشته `"2026-07-18"` (میلادی) هستن حتی وقتی تقویم شمسیه — شمسی فقط موقع «نمایش» ساخته می‌شه.
4. **عادت زمانی:** هدف و مقدار همیشه به **دقیقه** ذخیره می‌شن؛ «۱ ساعت و نیم» فقط شکل نمایششه (`formatDuration`).
5. **آینده ممنوع:** روزهای آینده فقط قابل مشاهده‌ان (`isFuture` در HabitRow، `disableFuture` در WeekStrip).
