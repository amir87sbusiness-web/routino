# راهنمای تبدیل Routino به اپ موبایل (iOS + Android)

این پروژه یک SPA خالص و مستقل است — بدون وابستگی به هیچ پلتفرم شخص ثالثی —
که با Capacitor برای اجرا به‌صورت اپ بومی iOS/Android آماده شده است، همراه
با نوتیفیکیشن واقعی سیستم‌عامل. کارهایی که از قبل انجام شده:

- `vite.config.ts` — یک بیلد واحد که با متغیر `BUILD_TARGET=mobile` خروجی
  را در `www/` می‌سازد (برای Capacitor)، و بدون آن در `dist/` (برای وب)
- `capacitor.config.ts` — تنظیمات Capacitor
- `src/lib/native-notifications.ts` — زمان‌بندی نوتیفیکیشن بومی (کار می‌کند
  فقط داخل اپ native، در وب بی‌اثر است)
- اتصال این ماژول به عادت‌ها (`state/app.tsx`) و تسک‌ها (`routes/tasks.tsx`)

مراحل زیر باید روی سیستم خودت (مک برای iOS، هر سیستمی برای اندروید) انجام شوند،
چون نیاز به Xcode / Android Studio دارند که این‌جا در دسترس نیست.

## مرحله ۱ — نصب پکیج‌ها

```bash
cd routino-1.2
npm install
```

## مرحله ۲ — بیلد اولیه‌ی وب استاتیک

```bash
npm run build:mobile
```

این خروجی را داخل `www/` می‌سازد. Capacitor همین پوشه را داخل اپ بومی نمایش می‌دهد.

## مرحله ۳ — افزودن پلتفرم‌ها (فقط یک‌بار)

```bash
npx cap add ios
npx cap add android
```

این دستورها دو پوشه‌ی `ios/` و `android/` می‌سازند — پروژه‌های واقعی Xcode و
Android Studio. این پوشه‌ها را باید به گیت اضافه کنی (commit کنی)، چون
حاوی تنظیمات نیتیو (آیکون، splash screen، مجوزها) هستند.

## مرحله ۴ — همگام‌سازی کد وب با پروژه‌ی نیتیو

هر بار که کد را تغییر دادی، این را اجرا کن:

```bash
npm run cap:sync
```

این کار سه چیز انجام می‌دهد: بیلد `www/` را می‌سازد، آن را داخل پروژه‌های
iOS/Android کپی می‌کند، و پلاگین‌های Capacitor (نوتیفیکیشن و غیره) را sync می‌کند.

## مرحله ۵ — باز کردن و اجرا در Xcode / Android Studio

```bash
npm run cap:ios       # پروژه را در Xcode باز می‌کند
npm run cap:android   # پروژه را در Android Studio باز می‌کند
```

از داخل Xcode یا Android Studio، روی دکمه‌ی ▶️ (Run) بزن تا روی شبیه‌ساز یا
گوشی واقعی متصل‌شده اجرا شود.

## پیکربندی نوتیفیکیشن — مراحل ضروری پلتفرمی

کد نوتیفیکیشن آماده است، اما هر پلتفرم یک تنظیم دستی کوچک نیاز دارد:

### iOS
داخل Xcode، تب **Signing & Capabilities** پروژه را باز کن و مطمئن شو
**Push Notifications** capability اضافه شده (حتی اگر فقط از Local
Notifications استفاده می‌کنی، بعضی تنظیمات مشترک است). برای نوتیف‌های
لوکال (`LocalNotifications`) که همین حالا وصل کرده‌ایم، نیازی به تنظیم
سرور پوش نیست — اپ خودش زمان‌بندی می‌کند.

### Android
هیچ تنظیم دستی اضافه‌ای برای Local Notifications لازم نیست؛ پلاگین خودش
مجوز `POST_NOTIFICATIONS` (اندروید ۱۳+) را در زمان اجرا درخواست می‌کند
(همان `requestNativePermission()` که در `native-notifications.ts` صدا زده می‌شود).

### تست کردن
1. اپ را روی گوشی/شبیه‌ساز اجرا کن.
2. در تنظیمات (Settings) اپ، سوییچ نوتیفیکیشن را روشن کن — این
   `requestNativePermission()` را صدا می‌زند و مجوز سیستم‌عامل را می‌گیرد.
3. برای یک عادت، `reminderTime` را روی ۱-۲ دقیقه‌ی بعد تنظیم کن.
4. اپ را کامل ببند (از لیست اپ‌های اخیر هم حذفش کن).
5. باید نوتیف در زمان مقرر ظاهر شود — این تفاوت اصلی با نسخه‌ی وب است.

## پوش نوتیفیکیشن سرور (اختیاری، برای بعداً)

آنچه الان پیاده‌سازی شده **Local Notifications** است: زمان‌بندی از قبل روی
خود گوشی، بدون نیاز به سرور. برای مواردی مثل «پیام از سمت ادمین به همه‌ی
کاربران بفرست» (که در `routes/admin.tsx` احتمالاً به آن نیاز داری) باید
**Push Notifications** واقعی راه‌اندازی شود که نیازمند:

- یک سرویس پوش (Firebase Cloud Messaging برای اندروید و اکثر پلتفرم‌های
  cross-platform، یا APNs مستقیم برای iOS)
- یک بک‌اند که device token هر کاربر را ذخیره و پیام پوش بفرستد

پکیج `@capacitor/push-notifications` که در `package.json` اضافه شده برای
همین مرحله‌ی بعدی آماده است، اما اتصال به FCM/APNs یک قدم جدا و
بزرگ‌تر است — وقتی به آن نیاز داشتی خبر بده تا آن بخش را هم مرحله‌به‌مرحله
پیاده کنیم.

## نکته‌ی داده‌ها (localStorage)

تمام دیتای اپ (عادت‌ها، تسک‌ها، ژورنال، تنظیمات) الان در `localStorage`
ذخیره می‌شود (`src/lib/store.ts`). این در WebView داخل اپ نیتیو هم کار
می‌کند و بین اجراهای اپ باقی می‌ماند، اما:

- بین دستگاه‌های مختلف کاربر sync نمی‌شود (چون کد داخل کامنت‌های `store.ts`
  هم اشاره کرده: "future REST/GraphQL sync adapter" هنوز پیاده نشده).
- اگر کاربر اپ را پاک‌سازی (uninstall) کند، همه‌ی داده از دست می‌رود.

اگر بخواهی sync ابری/بک‌آپ داشته باشی، آن هم یک مرحله‌ی جدا (نیازمند بک‌اند
واقعی به‌جای mock فعلی در `state/app.tsx`) است.

## نسخه‌ی وب / ویندوز (بعداً)

الان تمرکز روی موبایل است، اما وقتی خواستی نسخه‌ی وب یا دسکتاپ ویندوز را هم
منتشر کنی، کافی است:

```bash
npm run build       # خروجی استاندارد SPA در dist/
```

این خروجی هیچ وابستگی به Capacitor یا کد موبایل ندارد و مستقیماً روی هر
هاست استاتیکی قابل آپلود است. برای بسته‌بندی آن به‌عنوان یک اپ ویندوز
(exe)، ساده‌ترین راه Electron یا Tauri است — جزئیاتش را جدا بررسی می‌کنیم
هروقت به آن مرحله رسیدی. کد فعلی هیچ تغییری برای این مسیر نیاز ندارد.
