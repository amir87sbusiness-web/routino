# اجرا و انتشار وب‌اپ روتینو

راهنمای کامل: از اجرای محلی تا لانچ روی آروان کلاد.

> **می‌خواهی رایگان و روی routino.me لانچ کنی؟** این فایل مسیر آروان‌کلاد (هاست
> ایرانی) است. مسیر فعلی و رسمی لانچ رایگان
> [`DEPLOY-SUPABASE-EDGE.md`](DEPLOY-SUPABASE-EDGE.md) است (Cloudflare Pages +
> Supabase Edge Function). مسیر قدیمی‌تر Render در
> [`DEPLOY-FREE-STACK.md`](DEPLOY-FREE-STACK.md) دیگر توصیه نمی‌شود. بخش «۱.
> اجرای محلی» و «۷. قبل از لانچ واقعی» همین فایل برای هر سه مسیر معتبرند.

---

## ۱. اجرای محلی

روتینو دو تکه است: **وب‌اپ** (چیزی که کاربر می‌بیند) و **سرور** (ورود و اشتراک).

```bash
# ترمینال ۱ — سرور
cd backend
npm install
npm run dev          # روی :3000

# ترمینال ۲ — وب‌اپ
npm install
npm run dev          # روی :5180
```

بعد `http://localhost:5180` را باز کن.

**نکته:** سرور به هیچ چیزی نیاز ندارد — نه Docker، نه پستگرس نصب‌شده. یک پستگرس
واقعی داخل خودش اجرا می‌شود و روی `backend/.pglite-data` ذخیره می‌کند.

**کد پیامک کجاست؟** در حالت توسعه پیامکی ارسال نمی‌شود؛ کد در **ترمینال سرور**
چاپ می‌شود:
```
  [sms:console] OTP for 989123334444 -> 411794
```

### تست حالت آفلاین
حالت آفلاین فقط روی نسخه‌ی نهایی کار می‌کند (در حالت توسعه عمداً خاموش است تا
با hot-reload تداخل نکند):
```bash
npm run build
npm run preview      # روی :4173
```
بعد در DevTools → Network → **Offline** و صفحه را رفرش کن. باید کامل بالا بیاید.

## ۲. چه چیزی کجا می‌رود

| تکه | کجا | چرا |
|---|---|---|
| وب‌اپ (`dist/`) | **Object Storage + CDN آروان** | فقط فایل ثابت است؛ ارزان‌ترین و سریع‌ترین حالت |
| سرور (`backend/`) | **یک Cloud Server آروان** + Docker | به دیتابیس و اجرای دائم نیاز دارد |

```
کاربر → CDN آروان (وب‌اپ) ──/v1/──→ سرور آروان → پستگرس
```

## ۳. انتشار وب‌اپ روی آروان

### قدم ۱ — بیلد
```bash
VITE_API_URL=https://api.your-domain.ir/v1 npm run build
```
خروجی در `dist/`.

> `VITE_API_URL` **حین بیلد** داخل فایل‌ها می‌رود. اگر آدرس سرور عوض شد، باید
> دوباره بیلد بگیری.

### قدم ۲ — آپلود
تمام محتویات `dist/` را در یک باکت Object Storage آروان بگذار و باکت را روی حالت
**static website** بگذار.

### قدم ۳ — دو تنظیمی که اگر غلط باشند وب‌اپ می‌شکند

**الف) سند خطا را روی `index.html` بگذار.**
اپ روتینگ سمت کلاینت دارد. اگر کسی مستقیم `your-domain.ir/habits` را باز کند،
آبجکت‌استوریج دنبال فایلی به اسم `habits` می‌گردد و پیدا نمی‌کند → **۴۰۴**.
با ست‌کردن سند خطا روی `index.html` همه‌ی مسیرها کار می‌کنند.

**ب) کش را درست تنظیم کن — این مهم‌ترین تنظیم کل انتشار است.**

| فایل | `Cache-Control` |
|---|---|
| `index.html` | `no-cache` |
| `sw.js` | `no-cache` |
| `manifest.webmanifest` | `no-cache` |
| `/assets/*` | `public, max-age=31536000, immutable` |

**اگر `index.html` را کش کنی، کاربرها برای همیشه روی نسخه‌ی قدیمی یخ می‌زنند** و
هیچ آپدیتی نمی‌گیرند. فایل‌های `assets/` اسم هش‌دار دارند (`index-D3fdBn6U.js`)
پس کش‌کردن ابدی‌شان امن است — با هر بیلد اسمشان عوض می‌شود.

### قدم ۴ — CDN و دامنه
دامنه را به CDN آروان وصل کن و **SSL را روشن کن**.

> **HTTPS اجباری است.** مرورگرها سرویس‌ورکر را فقط روی HTTPS اجرا می‌کنند (جز
> `localhost`). بدون آن، حالت آفلاین و قابلیت نصب **اصلاً کار نمی‌کنند**.

## ۴. انتشار سرور

```bash
# روی VM آروان
cd backend
cp .env.example .env
```

`.env` را ویرایش کن — این‌ها را حتماً عوض کن:

```bash
NODE_ENV=production
DB_DRIVER=postgres                        # pglite فقط برای توسعه است

# با این دستور بساز:
#   node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
JWT_SECRET=<یک رشته‌ی تصادفی بلند>
OTP_PEPPER=<یک رشته‌ی تصادفی بلند دیگر>

POSTGRES_PASSWORD=<رمز قوی>

SMS_PROVIDER=kavenegar
KAVENEGAR_API_KEY=<کلید تو>

CORS_ORIGINS=https://your-domain.ir
PUBLIC_API_URL=https://api.your-domain.ir
PUBLIC_WEB_URL=https://your-domain.ir
API_DOMAIN=api.your-domain.ir
ACME_EMAIL=you@example.com

# ── محل نگهداری بکاپ، بیرون از این ماشین ───────────────────────────────
# بدون این‌ها بکاپ گرفته می‌شود ولی روی همین VM می‌ماند — یعنی اگر VM را از
# دست بدهی، دیتابیس و بکاپش با هم می‌روند. سرویس بکاپ در لاگش هر بار هشدار
# می‌دهد. یک باکت S3-سازگار بساز (آروان/لیارا/پارس‌پک) و **جدا از هر باکت
# عمومی** نگهش دار: این فایل‌ها دیتای همهٔ کاربرهاست.
S3_ENDPOINT=https://s3.ir-thr-at1.arvanstorage.ir
S3_BUCKET=routino-db-backups
S3_ACCESS_KEY=<کلید>
S3_SECRET_KEY=<رمز>
```

```bash
docker compose up -d
```

این کار پستگرس + سرور + Caddy (که خودش SSL می‌گیرد) + بکاپ روزانه را بالا می‌آورد.
اولین بکاپ **بلافاصله** گرفته می‌شود (نه ۲۴ ساعت بعد)، تا اگر چیزی در تنظیمات
S3 غلط باشد همان دقیقهٔ اول در لاگ ببینی، نه فردا.

> **بکاپ تست‌نشده تزئین است.** این را همین امروز یک بار اجرا کن:
>
> ```bash
> docker compose run --rm backup restore.sh
> ```
>
> جدیدترین بکاپ را از باکت برمی‌دارد، در یک دیتابیس موقت بازیابی می‌کند، تعداد
> ردیف‌ها را چاپ می‌کند و بعد پاکش می‌کند. **به دیتابیس اصلی دست نمی‌زند.**
> اگر عددها شبیه دیتای واقعی‌ات بود، بکاپت واقعی است.

## ۵. کاربر چطور «دانلودش» می‌کند

وب‌اپ از مارکت نصب نمی‌شود — از خود سایت.

**اندروید / کروم:** کاربر که سایت را باز کند، بنر «روتینو رو نصب کن» بالای صفحه
می‌آید. یک کلیک و آیکون روی صفحه‌ی گوشی می‌نشیند و مثل اپ معمولی (بدون نوار
مرورگر) باز می‌شود.

**آیفون / سافاری:** اپل دکمه‌ی نصب خودکار ندارد. اگر کاربر روی «نصب» بزند، راهنمای
دو قدمی فارسی نشان داده می‌شود: **هم‌رسانی → افزودن به صفحه اصلی**.

**دسکتاپ:** کروم یک آیکون نصب در نوار آدرس نشان می‌دهد.

بعد از نصب، اپ **بدون اینترنت هم باز می‌شود** و تمام اطلاعات روی خود دستگاه است.

## ۶. آپدیت‌ها

بیلد بگیر و `dist/` را دوباره آپلود کن. کاربرهایی که اپ را باز دارند یک اعلان
«نسخه‌ی جدید روتینو آماده‌ست» با دکمه‌ی بروزرسانی می‌بینند.

**عمداً خودکار آپدیت نمی‌شود:** اگر وسط کار کاربر فایل‌های اپ عوض شوند، اپِ در حال
اجرا خطا می‌دهد. انتخاب با خودش است.

## ۷. قبل از لانچ واقعی

- [ ] **قالب پیامک کاوه‌نگار** را تأیید بگیر — تأیید انسانی است و **چند روز طول
      می‌کشد**. تا نگیری هیچ کاربری نمی‌تواند وارد شود.
- [ ] `JWT_SECRET` و `OTP_PEPPER` و `ADMIN_TOKEN` را عوض کن (مقدار پیش‌فرض
      `dev-only` است و سرور در حالت production بالا نمی‌آید تا عوضشان کنی).
- [ ] بکاپ را با یک restore واقعی تست کن.
- [ ] **زیبال**: مرچنت واقعی بگیر و در `.env` بگذار: `PSP_PROVIDER=zibal` و
      `ZIBAL_MERCHANT=<کد مرچنت>`. کل ماشین حالت پرداخت (checkout → درگاه →
      callback → verify → فعال‌سازی) پیاده و تست شده؛ درگاه فیک همان قرارداد
      زیبال را دارد، پس فقط env عوض می‌شود. اولین تراکنش واقعی را خودت با
      کارت خودت بزن و در پنل `/admin` چک کن.
- [ ] `PUBLIC_API_URL` باید همان دامنه‌ی https سرور باشد — زیبال مرورگر کاربر را
      به `/v1/payments/callback` همین آدرس برمی‌گرداند.
- [ ] **پنل ادمین**: `https://api.your-domain.ir/admin` — با `ADMIN_TOKEN` وارد
      شو. آمار، کاربران (مسدودسازی/گرنت دستی)، پرداخت‌ها و ساخت کد تخفیف.
- [ ] **همگام‌سازی بین دستگاه‌ها هنوز نیست** — هر دستگاه اطلاعات خودش را دارد.
      برای نسخه‌ی اول قابل قبول است، ولی کاربر باید بداند.
- [ ] وضعیت `verify_failed` در پنل پرداخت‌ها یعنی مغایرت مبلغ — هرگز نباید رخ
      دهد؛ اگر دیدی همان روز پیگیری کن.

## ۸. عیب‌یابی

**«بنر نصب نمیاد»**
روی HTTPS هستی؟ قبلاً نصبش نکرده‌ای؟ قبلاً بنر را نبسته‌ای؟ (پاک‌کردن
`routino:install-dismissed` از localStorage برش می‌گرداند.) کروم هم گاهی قبل از
نمایش، کمی تعامل لازم دارد.

**«آفلاین کار نمی‌کنه»**
سرویس‌ورکر HTTPS می‌خواهد و روی `npm run dev` عمداً خاموش است. با
`npm run build && npm run preview` تست کن.

**«آپدیت دادم ولی کاربرها نسخه‌ی قدیمی رو می‌بینن»**
`index.html` کش شده. `Cache-Control: no-cache` روی آن بگذار.

**«باز کردن مستقیم /habits خطای ۴۰۴ می‌ده»**
سند خطای باکت روی `index.html` تنظیم نشده.
