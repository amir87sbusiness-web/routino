# Launch Copy, Android, and Operations Design

## هدف

روتینو با صفحه معرفی کوتاه و کاربرمحور، APK اندروید امضاشده و آماده آپلود، مصرف کنترل‌شده Supabase و لاگ‌های قابل پیگیری منتشر شود.

## صفحه معرفی

- ساختار و ریتم از PDF مرجع Productive الهام می‌گیرد: وعده روشن، معرفی کوتاه، قابلیت‌های اصلی، اقدام نهایی.
- متن فقط نیاز کاربر را توضیح می‌دهد: ساخت عادت، دیدن برنامه امروز، تمرکز، مشاهده پیشرفت، یادآوری، کار آفلاین و پشتیبان‌گیری.
- صفحه درباره معماری، Worker، Supabase، کش یا جزئیات امنیتی توضیح نمی‌دهد.
- هیچ آمار، جایزه، نظر کاربر یا ادعای همگام‌سازی چنددستگاهی ساخته نمی‌شود.
- تصمیم قبلی حفظ می‌شود: قیمت و دوره آزمایشی در صفحه عمومی نمایش داده نمی‌شود.
- متن فارسی محاوره‌ایِ تمیز و حرفه‌ای است؛ جمله‌ها کوتاه‌اند و هر قابلیت فقط یک فایده روشن دارد.

## دانلود اندروید

- خروجی یک APK یونیورسال Release برای Android 6 به بالا با package فعلی `com.routino.app` است.
- APK با کلید دائمی خارج از Git امضا می‌شود. فایل کلید و رمزها هرگز commit نمی‌شوند.
- امضا با `apksigner verify`، محتوای APK با `apkanalyzer` و مجوزها با manifest نهایی بررسی می‌شوند.
- کنار APK فایل SHA-256 و metadata شامل versionCode، versionName، package و fingerprint گواهی ساخته می‌شود.
- فایل نهایی در `output/android/` تحویل می‌شود تا مالک آن را در فضای ابری دلخواه آپلود کند.
- لینک سایت از متغیر build به نام `ANDROID_DOWNLOAD_URL` پر می‌شود. تا قبل از ارائه لینک، دکمه غیرفعال و صادقانه باقی می‌ماند.
- نصب خارج Google Play همچنان اجازه استاندارد «Install unknown apps» را در Android می‌خواهد؛ محصول ادعا نمی‌کند این هشدار قابل حذف است.

## مصرف Supabase و Worker

- محتوای شخصی همچنان فقط لوکال است و هیچ مسیر sync دوباره فعال نمی‌شود.
- Worker پاسخ `/health` و CORS preflight را بدون اجرای Supabase Edge Function می‌دهد.
- `/v1/plans` در Worker کش می‌شود و درخواست‌های هم‌زمانِ miss در همان isolate یکی می‌شوند.
- چک دوره‌ای نشست به endpoint سبک `/v1/devices/ping` تغییر می‌کند؛ فهرست کامل دستگاه‌ها فقط در صفحه تنظیمات خوانده می‌شود.
- تازه‌سازی entitlement از چک امنیتی جدا و با TTL شش‌ساعته محدود می‌شود، ولی در ورود، بازگشت پرداخت، انقضا و نیاز به تأیید آنلاین فوراً تازه می‌شود.
- چک امنیت دستگاه در boot، online، foreground و دوره visible حفظ می‌شود؛ شکست شبکه باعث خروج یا پاک‌شدن داده نمی‌شود.

## لاگینگ و فشار

- Worker و Edge برای هر درخواست `x-request-id` مشترک دارند.
- لاگ‌ها JSON، کوتاه و بدون access token، refresh token، OTP، رمز، متن ژورنال یا محتوای شخصی‌اند.
- خطاها، پرداخت، امنیت دستگاه و عملیات ادمین همیشه ثبت می‌شوند؛ درخواست‌های عادی فقط در حالت کند یا با نمونه‌برداری ثبت می‌شوند.
- کلاینت یک بافر محلی محدود برای رویدادهای فنی دارد که محتوا و شناسه حساس در آن نیست و با پاک‌کردن خودکار قدیمی‌ها رشد نمی‌کند.
- تست فشار روی Fastify و Edge محلی با PGlite انجام می‌شود. Production فقط smoke test محدود می‌گیرد تا سهمیه یا سرویس واقعی تحت فشار مصنوعی قرار نگیرد.

## انتشار و معیار پذیرش

1. تست‌های frontend، backend و Edge، typecheck، build وب و build موبایل پاس باشند.
2. APK امضاشده نصب شود، برنامه آفلاین باز شود و اتصال API روی Android کار کند.
3. متن landing در موبایل و دسکتاپ بدون بریدگی و ادعای نادرست نمایش داده شود.
4. API/Edge پیش از وب منتشر شود؛ سپس Worker، Git main و سایت منتشر شوند.
5. Loop پس از انتشار health، ready، plans، صفحه اصلی و دانلود را پایش کند.
6. اگر ورود Cloudflare یا لینک فایل ابری در دسترس نباشد، بقیه انتشار کامل می‌شود و فقط همان مرحله با دلیل دقیق باز می‌ماند.
