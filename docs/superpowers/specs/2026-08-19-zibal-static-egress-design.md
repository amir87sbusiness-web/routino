# طراحی مسیر پرداخت زیبال با IP ثابت

## مسئله

درخواست واقعی پرداخت در Supabase Edge با کد زیبال `115` رد می‌شود. معنی این کد این است که IP خروجی درخواست در تنظیمات درگاه ثبت نشده است. Supabase Edge و Cloudflare Worker معمولی IP خروجی ثابت و اختصاصی ندارند؛ بنابراین ثبت IP فعلی هرکدام راه‌حل پایدار نیست.

## تصمیم

مسیر عمومی روتینو بدون تغییر باقی می‌ماند:

`برنامه → api.routino.me (Cloudflare Worker) → Supabase Edge`

فقط دو تماس سروربه‌سرور زیبال (`request` و `verify`) از یک رلهٔ کوچک دارای IPv4 ثابت عبور می‌کنند:

`Supabase Edge → رلهٔ امضاشده → gateway.zibal.ir`

IP خروجی میزبان رله تنها IP ثبت‌شده در پنل زیبال خواهد بود. Cloudflare Worker همچنان ورودی عمومی، CORS، کش پلن‌ها و پنهان‌کردن آدرس خام Supabase را مدیریت می‌کند؛ اما مستقیماً نقش IP ثابت را بازی نمی‌کند.

## قرارداد امنیتی رله

- رله فقط `POST /v1/request` و `POST /v1/verify` را قبول می‌کند.
- بدنه حداکثر ۸ کیلوبایت است و رله مقدار `merchant` را همیشه از secret خودش جایگزین می‌کند.
- Supabase هدرهای `x-routino-timestamp`، `x-routino-nonce` و `x-routino-signature` را می‌فرستد.
- امضا HMAC-SHA256 روی رشتهٔ `timestamp\nnonce\npath\nrawBody` است.
- درخواست بیش از ۶۰ ثانیه، nonce تکراری، امضای نامعتبر، مسیر دیگر یا JSON نامعتبر رد می‌شود.
- رله پاسخ خام زیبال را بدون ذخیره‌کردن اطلاعات کارت عبور می‌دهد و هیچ endpoint عمومی پرداخت یا صفحهٔ HTML ندارد.
- health check محلی است و زیبال یا Supabase را صدا نمی‌زند.

## مصرف سهمیه

- داده‌های شخصی همچنان لوکال هستند.
- Worker فقط همان درخواست‌های فعلی API را عبور می‌دهد و `/v1/plans` را کش می‌کند.
- رله فقط هنگام شروع یا تأیید پرداخت بیدار می‌شود؛ cron، polling، queue و دیتابیس جدا ندارد.
- retry در رله انجام نمی‌شود تا یک تماس مبهم به زیبال دوباره ایجاد نشود؛ recovery موجود روتینو از callback و poll، verify را تکرارپذیر انجام می‌دهد.
- لاگ موفقیت شامل فقط نوع عملیات و زمان پاسخ است؛ بدنه، merchant، موبایل، کارت و امضا لاگ نمی‌شوند.

## سازگاری و انتشار

- در توسعه و تست، وقتی `ZIBAL_RELAY_URL` خالی است، آداپتور مستقیم فعلی حفظ می‌شود.
- در پروداکشن، `ZIBAL_RELAY_URL` و `ZIBAL_RELAY_SECRET` باید باهم تنظیم شوند؛ تنظیم ناقص باعث fail-fast در boot می‌شود.
- رله به‌صورت سرویس Node بدون dependency و با Dockerfile عرضه می‌شود تا روی هر VPS/فضای ابری دارای IPv4 ثابت اجرا شود.
- تا زمانی که IPv4 ثابت رله در پنل زیبال ثبت نشده، انتشار کد به‌تنهایی خطای `115` را برطرف نمی‌کند.
